# 文章结构化正文与版本记录

海燕传信继续使用 Vue、Tiptap、Spring Boot 和 MySQL。编辑过的正文同时保存 Tiptap 结构化文档和经过服务端校验、清理的 HTML；阅读、搜索和媒体权限仍由服务端处理。公开作品的草稿与已发布内容分别保存，自动保存不会直接更新访客看到的正文或图片。

## 作者使用

- 草稿自动保存；已发布文章的后续修改也会保存为私密草稿，作者选择“检查并更新发布”后才更新公开作品。
- 每次成功发布记录一个历史正文版本。编辑页可查看并载入历史正文，载入会替换当前正文并保存为草稿；标题和其他作品信息不会跟随历史正文恢复。仍需作者检查后主动发布。
- 如果其他页面已修改同一篇稿件，保存会提示冲突。当前页面的内容会留在编辑器中，作者应先复制需要保留的内容，再刷新后重新编辑。
- 旧文章保留现有 HTML。仅修改作品信息时不会强制转换正文；编辑正文后按当前编辑器结构保存。迁移时已发布的文章保留一份初始正文版本；更早的修改历史无法凭当前数据还原。

2026-11-02 已对本机数据库中的 26 篇已发布作品批量生成结构化草稿及对应的初始历史正文，原公开 HTML 保持不变。转换前备份位于本机受保护的 `.local/backups/`。此操作没有连接或更新云端数据库；以后从旧格式导入的文章仍遵循上述渐进转换规则。

## 存储和安全

Flyway V17 新增私密草稿、发布版本及各自的媒体引用。`works` 和 `work_media` 继续保存公开作品和公开图片引用，搜索、标签及合集使用公开数据。服务端校验结构化正文的节点和属性，并将其生成的 HTML 与清理后的正文核对；图片仍须属于当前账号。草稿与历史版本接口只允许作品作者访问。

发布在事务中更新公开正文、纯文本、作品信息和媒体关系并记录版本；版本恢复会经过正常的保存和发布校验。已有 HTML 不批量覆盖，旧作品首次编辑应检查特殊排版、图片说明和折叠内容。

## 部署与恢复

部署前停止写入，备份 MySQL 和 `data/images/`，并在隔离环境验证备份恢复与 V17 迁移。Flyway 启动时自动执行新增迁移；不要改写已经应用的迁移文件。数据库与图片需在同一备份时间点保管，因为草稿和历史版本可能引用当前公开正文以外的图片。

回退程序前先备份当前数据库和图片。旧程序不理解私密草稿与版本表，回退到旧程序后这些新数据不会自动显示，且旧程序可能改变公开作品；应先验证数据导出和恢复流程，避免回退期间产生新的写入。
