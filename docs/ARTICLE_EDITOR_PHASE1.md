# 文章编辑与阅读：第一阶段

本次在现有 Vue 3 / Tiptap / Java / MySQL 基础上实现。仍以 HTML 保存正文，没有协作服务或额外常驻进程。后续体裁版式扩展使用 V10 增量迁移保存版式和自定义体裁名称。

## 使用

- 空段落输入 `/` 打开插入菜单，上下键选择、回车插入、Esc 关闭；工具栏的“插入”也可点击或触屏操作。菜单包含正文、小标题、次级小标题、引用、两种列表、图片、分隔线和折叠内容。
- 保留加粗、斜体、标题、引用、列表、撤销/重做；旧正文中的下划线、删除线与换行继续保留。
- 图片下方直接编辑说明文字。点击图片或将光标放在说明中，可以选择“正文宽度”或“较窄显示”。较窄图片在桌面为正文的 65%，手机为 80%，均居中且不超过正文宽度。
- 折叠标题和内部正文均可编辑。编辑时始终展开，阅读及预览中可收起。首版仅允许一层折叠；粘贴的嵌套折叠会展开为普通内容，保留文字。
- 阅读预览与实际阅读页共用安全渲染和排版。目录只在存在 h2/h3 时出现，点击折叠区域中的标题会先展开区域；重复标题的锚点独立。
- 图片支持懒加载和大图对话框，按钮与 Esc 均可关闭。使用现有图片版本，不宣称提供未压缩原图。

## HTML 约定及安全

```html
<figure data-size="narrow">
  <img src="/api/media/合法UUID" alt="图片描述" width="1200" height="800">
  <figcaption>说明文字，可含有限的行内格式</figcaption>
</figure>
<details>
  <summary>折叠标题</summary>
  <div data-disclosure-body=""><p>折叠正文</p></div>
</details>
```

- `data-size` 仅接受 `full` / `narrow`；宽高仅保留成对的正整数，单边不超过 8000。旧 `<img>` 可直接读取，编辑后转换为 figure。
- `WorkHtml` 在 Java 端通过 Jsoup 清理并规范化结构。仍逐一验证媒体地址与上传者归属，再维护 `work_media` 访问关系。禁止任意 style、事件属性、脚本、iframe、srcset 和外部媒体地址。
- `html.ts` 使用 DOMPurify 独立清理已保存内容、预览和富文本剪贴板，再限制逐标签属性与媒体路径。不能因为内容来自编辑器而跳过清理。前后端白名单需要一起维护。
- 说明文字、summary 与折叠正文均进入 Jsoup 纯文本提取，沿用摘要、搜索、字数与发布审核流程。正文仍限制 20 万字符。
- 目录 ID 只在渲染时生成，以作品命名空间、标题哈希、同名序号构成；清除外来 ID。不同标题前插不会改变现有标题锚点，改名或重排同名标题时序号可能变化。

## 保存、上传与资源

- 草稿沿用 1.8 秒防抖，请求串行；真正发送时才截取表单快照，响应不回写编辑中的正文。输入法组合期间延后保存，上传和导入期间等待操作完成；重复点击保存不会并发发送。
- 已发布文章的修改继续要求明确发布。发布响应返回前继续输入时，不离开编辑器、不清除脏状态，并提示有新修改尚未发布。
- 图片一次处理一张，失败保留正文并提供重试、取消。发布会要求先解决失败图片；草稿仍可保存文字。
- 浏览器接受 PNG/JPEG，选择文件最大 20 MB、2000 万像素、边长 8000；在需要时压到最长边 1600 后上传。服务端仍独立检查 PNG/JPEG、5 MB、2000 万像素与边长 8000，继续重编码移除元数据，并返回最终宽高。
- 服务端图片解码并发限制为 1；繁忙时返回可重试错误。没有新增服务器常驻进程，原有 JVM 768 MB 上限与 5 个数据库连接保持不变。
- 阅读路由不加载完整编辑器。DOMPurify 与正文组件是共享的延迟加载模块；Playwright、jsdom 仅是开发测试依赖，不进入生产包。

## 验证与复跑

在根目录使用项目自带工具链：

```powershell
. ./tools/Use-Environment.ps1
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run test:e2e
./tools/Build.ps1
```

浏览器测试通过标准 `npm run dev` 启动短时 Vite 服务，API 全部使用隔离测试响应，不创建账号、作品或上传文件。Windows 默认使用已安装 Edge；其他环境可先在 frontend 下运行 `npx playwright install chromium`，也可通过 `PLAYWRIGHT_CHANNEL` 指定浏览器。

测试涵盖旧文章格式往返、新格式恢复、非法 HTML、外部/伪造/无权限媒体、折叠正文审核、上传校验、保存失败重试、请求顺序、发布期间继续输入、菜单键盘操作、输入法事件抑制、手机触屏入口、重复目录标题和大图关闭。截图输出在 `output/article-upgrade/`，桌面 1440×1000、手机 390×844。

本次验证：43 项后端测试、9 项前端测试、8 项 Edge 浏览器测试全部通过；`Build.ps1` 的类型检查、生产构建、Maven verify 与 JAR 打包通过。浏览器回归还验证了 2400×1200 图片在上传前缩为 1600×800，以及文档导入的空行保留。阅读共享模块约 14.1 KB gzip，完整编辑器约 129.4 KB gzip，仅编辑路由加载。

边界：输入法采用浏览器 composition 事件回归，尚未逐一验证真实系统输入法或 iOS Safari；没有在真实 Linux 2 核 2 GB 服务器上进行负载测试。失败内容保留在当前编辑页，仍应避免强制关闭浏览器；本阶段不增加离线草稿仓库或跨标签页并发编辑协调。

## 体裁与版式扩展

编辑页的“体裁”下显示当前版式与“设置版式”入口。切换体裁自动应用对应预设；手动调整或载入已保存作品时保留作者的选择。弹窗先展示体裁预设和排版示例，“细节调整”折叠收纳正文对齐、行距、段距/节距、节标题对齐和两字首行缩进。点击“应用版式”后才更新文章；取消、Esc 或点击遮罩关闭会放弃本次调整。“恢复默认”只改变弹窗内的待应用设置。

| 体裁 | 默认版式 |
| --- | --- |
| 诗歌 | 2.7 倍行距、紧凑段距；靠左或居中两种预设；空白段落压至约 0.7em 高 |
| 小说 | 节标题（h2/h3）居中，正文靠左、首行缩进两字 |
| 散文 | 舒展行距与较宽段距，无强制首行缩进 |
| 随笔 | 较紧凑行距与标准段距 |
| 其他 | 沿用原默认行距、段距与靠左排版，可填写最多 30 字的具体体裁名称 |

空段、仅含空格/全角空格的段落和仅含换行的段落都作为分节空行处理。编辑区通过 ProseMirror decoration 标记，阅读和预览在安全渲染后标记；标记不写入正文，不删除或合并空段。版式由有限的 CSS 类控制，不向 HTML 白名单开放作者提供的 style 或 class。

V10 仅向 works 增加 `custom_genre` 与可空的 `body_layout` 字段。旧文章未配置版式时根据体裁取默认值，不回写原正文；旧客户端省略版式时，同体裁编辑会保留已保存设置。自定义体裁仍属于“其他”筛选分类，阅读页显示具体名称。版式使用固定枚举，服务端独立校验后保存，自定义体裁接受长度检查与发布文字审核。

主要代码：`frontend/src/article/layout.ts`、`components/ArticleLayoutMenu.vue`、`article/editorExtensions.ts`、`article/article.css`，以及后端 `service/ArticleLayout.java` 和 `V10__article_layout_and_custom_genre.sql`。

扩展验证：48 项后端测试、10 项前端测试、9 项浏览器测试全部通过，包含自动预设、手动覆盖、诗歌空行高度、保存恢复、自定义体裁和预览/阅读一致性；完整构建、JAR 打包与标准本地健康检查通过。已检查桌面及手机尺寸截图，新增截图文件以前缀 `layout-` 保存。

## 版式弹窗与草稿删除

- 弹窗使用原生 dialog，保留键盘焦点、Esc 关闭和手机操作，关闭后恢复页面滚动与设置入口焦点；预览和临时设置不触发草稿保存，只有应用后的变化进入现有保存流程。
- “我的书桌”的全部稿件和草稿箱，在卡片、横条两种布局中都提供删除入口。草稿和已撤回稿件可删除，删除前确认且说明无法恢复，提交期间禁止重复操作；失败显示明确提示并保留列表项。
- `DELETE /api/member/works/{id}` 要求登录、CSRF、WRITE 权限及稿件归属。仅接受 DRAFT / WITHDRAWN，已发布稿件必须先撤回。
- 删除与保存使用相同的作者锁，并在事务中锁定稿件状态，防止与自动保存或发布相互覆盖。先清理稿件的标签、媒体关系、历史合集关系、互动和评论，再删除稿件；保留合集、笔名、上传媒体记录及实际文件，不影响其他作品对同一图片的引用。
- 本次没有数据库结构迁移。浏览器删除回归使用隔离响应，不删除真实账号的稿件。截图：`layout-dialog-desktop.png`、`layout-dialog-mobile.png`、`draft-delete-desktop.png`、`draft-delete-mobile.png`。

验证结果：79 项后端测试、10 项前端测试、10 项浏览器测试通过；完整生产构建与 JAR 打包通过。覆盖取消/Esc 不应用、触屏弹窗、应用后保存恢复、删除取消/失败/成功、重复点击、归属与状态限制、关联清理及登录/CSRF 边界。
